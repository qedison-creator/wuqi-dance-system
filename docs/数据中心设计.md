# 数据中心设计文档（v6 终版）

> 2026-10-02 实施一期+二期。定位：只读视角层，"一眼看懂生意"。现有功能与数据流零改动。

## 1. 三层架构与账本合同

```
功能层（可随意改/删）：运营页统计、套餐状态页、薪酬页等 —— 只是账本之上的视图
数据中心层：独立聚合账本，不经手任何统计接口
账本层（事实集合，append-only，受合同保护）：
  Booking / Attendance / CoachAttendance / CoachSalaryStat / SalaryBill
  PackageChange / PackageActivation / PackageExtension
  PackageLifecycleEvent（新）/ DcAlertFollowup（新）/ DcSavedReport（新）
  UserPackage（当前状态）
```

**账本合同（长期有效）**：
1. 账本字段只增不改不删；事实记录只追加不物理删除（作废用状态标记，如课薪 voided）；
2. 任何新功能写账本必须带快照（会员/套餐/课程姓名字段）；
3. 改账本写入逻辑（如薪酬V3）前必须跑 `smoke-datacenter.js` 对账通过。

**软删约束**：会员/教练未来若加删除，必须软删（status: 'deleted'），数据中心靠快照兜底显示；硬删违反本合同。

## 2. 数据来源与口径

| 数据 | 来源 | 口径 |
|---|---|---|
| 上课消耗（课时） | Booking completed，Σ credits_deducted | 不限次/每日1节卡的课同样计入（预约时记录 credits_deducted） |
| 有效期缩短/恢复 | Booking.shrink_days | 预约缩短 N 天，取消恢复 |
| 套餐录入/调整 | PackageChange | changes 里 total_credits 0→N 判定为"录入" |
| 套餐激活 | PackageActivation | |
| 套餐续期 | PackageExtension | |
| 套餐用完/到期 | PackageLifecycleEvent | pre('save') 钩子 + findByIdAndUpdate 路径补写（booking.service 主链路） |
| 教练课时 | CoachAttendance（archived:false, not_counted:false） | 教练删除后靠 coach_name 快照 |
| 教练薪酬 | CoachSalaryStat active 求和；有关联 bill_id = 已入账单 | staff 角色接口层剥离金额 |
| 提醒（到期/次数不足/很久没来） | stats.service.getPackageStatusList（与套餐状态页同源阈值） | |
| 提醒（过期未续/高频取消/还没上第一节课） | 数据中心派生，阈值存 Config `datacenter_alert_config` | 默认：过期窗口30天 / 当月取消≥3次 / 办卡3天未上课 |

## 3. 权限矩阵

| 角色 | 会员记录/提醒/榜单 | 教练页 | 薪酬金额 | 汇总（速览/热度/到期/耗卡） | 导出 |
|---|---|---|---|---|---|
| super_admin | ✓ 全门店 | ✓ | ✓ | ✓ | ✓ |
| store_manager | ✓ 本店 | ✓ | ✓ | ✓ | ✓ |
| staff | ✓ 本店 | ✓ | ✗ 接口剥离 | ✓ | ✓（无薪酬指标） |
| reviewer | ✗ 403 | ✗ 403 | ✗ 403（coach-salary 路由全量拦截） | ✓（仅汇总，会员维度 403） | ✗ 403 |

双保险：数据中心路由 `noReviewer` 中间件 + 全局 `dataMasking` 中间件 + coach-salary 路由顶部 reviewer 拦截。

## 4. 接口清单（/api/v1/datacenter）

汇总（reviewer 可见）：`GET overview / heatmap / expiry-trend / credits-distribution`
明细（reviewer 403）：`GET member-ledger / alerts / rankings / coach / heatmap-cell / report(会员维度403)`
写操作：`POST alerts/followup`、`GET/POST/DELETE reports`、`GET/PUT alert-config`（PUT 仅超管）
导出：`GET export/ledger / export/report`（返回 CSV 文本，前端写剪贴板+本地文件）

## 5. 溯源与删除保护

- 记录展示一律"快照优先，关联回退"，实体被删显示"已删除会员/已删除教练"；
- Booking/Attendance/CoachAttendance/Package 三台账自带快照；UserPackage 有 member_snapshot/package_snapshot；
- 一切历史记录不因任何实体删除而消失（append-only 合同）。

## 6. 三期预留（字段/设计已留，未实现）

- 套餐商品化：账本类型枚举预留 `recharge/payment/refund`；流水字段规范预留 `order_id / order_amount / pay_channel / pay_method`；
- 财务口径（仅文档）：消耗课时 × 消耗时点套餐单价（金额÷总课时，录入时快照）= 收入确认；Σ 在用套餐剩余课时 × 单价 = 预收余额；
- CRM：会员跟进记录集合（dc_alert_followups 的跟进标记是雏形）；
- WebSocket：现有 websocket.service 可扩展 datacenter 频道做实时速览/到店播报（一期未启用，回溯型数据 onShow/下拉刷新已足够）。
