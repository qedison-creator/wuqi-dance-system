## 一、目标与范围

### 1.1 本期目标

会员（含注册未审核用户）在小程序内购买舞蹈套餐，支付成功后自动获得权益并转为正式会员，随后沿用现有预约、扣课、候补、签到体系使用权益；管理端可配置支付参数、管理商品、查看订单、处理开票、随时开关购买功能。

### 1.2 本期范围（P0）

1. 管理端支付设置（商户号、AppID、证书序列号、APIv3 密钥、商户私钥、微信支付公钥/公钥 ID、回调地址），加密存储与配置自检。
2. 管理端商品管理：创建、编辑、删除、上架、下架、排序、库存、限购、门店归属。
3. 商品类型：时间卡、次卡、单次卡、私教课（不含场地租用在线售卖）。
4. 会员端购买闭环：商城 → 详情 → 确认订单 → 微信支付 → 结果页 → 权益到账 → 去预约。
5. 订单：创建、支付、主动查单、超时关单、列表/详情、取消、状态机、补发权益。
6. 开票：会员登记开票信息，管理端查看并手动开具/驳回。
7. 购买功能开关：全局 + 门店双级，三层校验；订单与发票不受影响。
8. 私教课：管理端排"私教"类型课程，购买私教课包的会员在预约页正常预约。
9. 注册用户购买后自动转正式会员。
10. 微信支付合规：签名、验签、幂等、金额校验、关单、日志、发货信息上报。

### 1.3 不在本期范围

- 线上退款（P1）、优惠券/拼团/分销、储值/礼品卡、在线选教练/选场地、微信电子发票、分账。

## 二、现状与复用结论

### 2.1 技术栈

| 层 | 现状 |
|---|---|
| 后端 | Express 5 + Mongoose 9 + MongoDB 单节点；`node-cron`；WebSocket |
| 会员端 | 原生小程序，三套皮肤（经典/paper/volt），分包 `package-sub` |
| 管理端 | 原生小程序，分包 `package-shop / package-member / package-settings / package-schedule / package-common / package-data` |
| 支付 | 无任何支付代码，需从零接入 |

### 2.2 复用清单

| 能力 | 复用方式 |
|---|---|
| `UserPackage` | 购买权益沿用同一模型，预约/扣课/限额/停卡/延长/提醒不变 |
| `packageService.activatePackageById` | 首次预约/手动激活沿用现有逻辑 |
| `packageService.createPackage` 的建包规则 | 购买建包复用其字段、快照、赠送与自动激活时间规则 |
| `memberService.generateMemberCode` | 购买转正时生成会员编码 |
| `Store` / `storeFilter` | 商品与订单门店隔离 |
| `Config` + `Store` 字段 | 购买开关 |
| `logService` | 商品、订单、开票、支付配置变更审计 |
| `sendToUser` WebSocket | 支付成功后推送 `package_update`、转正后推送会员状态更新 |
| 现有提醒服务 | 已购套餐自动纳入到期/低次数提醒 |

### 2.3 必须处理的耦合点

1. **自购套餐污染「套餐录入记录」**：`getEntryRecords` 直接扫 `UserPackage`，需加 `source` 并排除自购记录。
2. **激活记录枚举**：`PackageActivation.activation_type` 新增 `purchase`。
3. **单节点 MongoDB 无事务**：唯一索引 + 条件更新 + 幂等 + 定时补偿。
4. **回调原文**：`app.js` 全局 `express.json()`，需为回调保留 `rawBody`。
5. **套餐匹配点分散**：私教课程限制需在会员预约、管理端代约、候补转正、现场签到、现场补签全部入口生效（项目既有教训：限额口径必须覆盖所有入口）。
6. **三套皮肤**：新页面必须按皮肤实现，禁止样式串味。

## 四、数据模型

> 新增模型金额统一用**分（整数）**；现有 `Package.price` 为元，不复用。

### 4.1 `Product` 套餐商品

| 字段 | 类型 | 说明 |
|---|---|---|
| product_no | String unique | 商品编号 `SP+日期+序号` |
| name / subtitle | String | 名称 / 卖点副标题 |
| category | Enum | `time_card` / `count_card` / `single_card` / `private_class` |
| store_id | ObjectId | 归属（履约）门店 |
| extra_store_ids | [ObjectId] | 可跨店使用门店（仅超管可设） |
| cover_url / banner_urls | String / [String] | 封面、图集 |
| detail_html | String | 图文详情 |
| price / original_price | Number(分) | 售价 / 划线价 |
| stock | Number / null | 库存，null=不限 |
| sold_count | Number | 已售 |
| per_user_limit | Number | 每人限购，0=不限 |
| sale_status | Enum | `draft` / `on_sale` / `off_shelf` |
| sale_start_at / sale_end_at | Date | 售卖时间窗 |
| sort_order / is_recommended | Number / Boolean | 排序 / 推荐 |
| benefit | Object | 权益配置（见 4.2） |
| refund_policy / refund_note | Enum / String | `unused_full` / `prorated` / `non_refundable` |
| invoice_supported | Boolean | 是否可开票 |
| purchase_notice | String | 购买须知 |
| agreement_version | String | 协议版本 |
| is_deleted | Boolean | 软删除（有订单禁止物理删） |
| created_by / updated_by | ObjectId | 操作人 |

索引：`product_no` 唯一、`{store_id, sale_status, sort_order}`、`{category}`、`{sale_start_at, sale_end_at}`。

### 4.2 `benefit` 权益配置

```
package_type         count_card | time_card
total_credits        Number              // 次卡/单次卡/私教课时数；时间卡为 0
duration_value       Number
duration_unit        month | day
daily_limit          Number | null
weekly_limit         Number | null
monthly_limit        Number | null
dance_style_limit    [ObjectId]
weekday_limit        [Number]
usable_before        String              // HH:mm
usable_after         String              // HH:mm
class_type_limit     group | private | null   // 私教商品固定 private
activation_mode      inherit             // 固定"沿用现有激活规则"
bonus_credits        Number              // 可选赠送课时
```

### 4.3 `Order` 订单

| 字段 | 说明 |
|---|---|
| order_no | 唯一商户订单号 `WQ+yyMMddHHmmss+6位随机` |
| user_id / openid | 会员与下单 openid 快照 |
| product_id / product_snapshot | 商品与下单快照（含权益、门店名、退款规则） |
| store_id | 履约门店 |
| amount_total / amount_payable / paid_amount | 金额（分） |
| status | `pending_esign / pending_payment / paid / completed / cancelled / closed / refunding / refunded / refund_failed`（`pending_esign` 仅 P1 启用） |
| pay_expire_at | 创建后 15 分钟（电子签场景为签署完成后 15 分钟） |
| prepay_id / transaction_id | 预支付单号 / 微信订单号（唯一稀疏） |
| paid_at / closed_at / cancel_reason | 时间与原因 |
| user_package_id | 权益结果 |
| fulfill_status / fulfill_error | `none/processing/success/failed` + 原因 |
| invoice_status | `none/applied/issued/rejected` |
| agreement_version / agreement_hash | 下单时确认的协议版本与全文哈希 |
| agreement_consent_id | 关联 `AgreementConsent` 签署凭证 |
| esign_status | `none / pending / signed / failed`（P1 第三方电子签） |
| user_snapshot | 会员姓名、手机号快照 |
| client_ip / source | 风控 / `miniprogram` |

索引：`order_no` 唯一、`transaction_id` 唯一稀疏、`{user_id, created_at}`、`{status, pay_expire_at}`、`{store_id, status}`。

### 4.4 `PaymentConfig` 支付参数（管理端配置）

| 字段 | 说明 |
|---|---|
| mchid | 商户号 |
| appid | 支付 AppID（默认等于会员端 AppID） |
| serial_no | 商户 API 证书序列号 |
| api_v3_key_enc | APIv3 密钥密文 |
| private_key_enc | 商户私钥 PEM 密文 |
| public_key_enc / public_key_id | 微信支付公钥密文 / 公钥 ID |
| notify_url / refund_notify_url | 回调地址（默认按当前域名生成，可改） |
| enabled | 是否启用真实支付（false 时可使用 Mock，仅非生产） |
| updated_by / updated_at | 操作人 |

- 加密：AES-256-GCM，主密钥来自服务器 `.env` 的 `PAY_CONFIG_SECRET`（32 字节）。主密钥是唯一必须由运维配置的密钥。
- 读取接口只返回 `{ configured, mchid_masked, appid, serial_no_masked, public_key_id, enabled, updated_at }`。
- 支付服务缓存配置 60 秒，保存后主动失效。

### 4.5 `PaymentNotifyLog`

`notify_id` 唯一、`event_type`、`order_no`、`verified`、`raw_body`、`processed`、`error`、`created_at`。

### 4.6 `RefundOrder`（P1 使用，本期先建）

`refund_no` 唯一、`order_id`、`out_refund_no`、`amount`、`reason`、`status`、`wx_refund_id`、`operator_id`、`success_at`。

### 4.7 `InvoiceRequest`

`order_id`、`user_id`、`type`（personal/company）、`title`、`tax_no`、`email`、`phone`、`remark`、`amount`、`status`（pending/issued/rejected）、`invoice_no`、`file_url`（可选）、`reject_reason`、`issued_by`、`issued_at`。

### 4.8 现有模型增量

| 模型 | 增量 |
|---|---|
| `UserPackage` | `source`（admin/purchase/system，默认 admin）、`order_id`、`product_id`、`paid_amount`、`class_type_limit`（null 兼容存量） |
| `PackageActivation` | `activation_type` 新增 `purchase` |
| `Store` | `package_purchase_enabled`（Boolean/null，null=继承） |
| `Schedule` | `class_type`（`group`/`private`，默认 group） |

### 4.9 `Config` 新增键

| key | 默认 | 说明 |
|---|---|---|
| `package_purchase_enabled` | `'false'` | 全局开关，上线默认关闭 |
| `package_purchase_closed_notice` | `'套餐购买暂未开放，如需咨询请联系门店'` | 关闭提示文案 |

### 4.10 `Agreement` 协议版本

| 字段 | 说明 |
|---|---|
| code | 协议编码：`package_purchase` / `refund_policy` / `privacy` |
| version | 版本号，如 `v1.0` |
| title | 协议标题 |
| content_html | 协议全文（保存快照） |
| content_hash | 全文 SHA-256，用于防篡改校验 |
| effective_at | 生效时间 |
| status | `draft` / `published` / `archived` |
| published_by / published_at | 发布人 / 时间 |

规则：同一 `code` 同时只有一个 `published` 版本；新版本发布时旧版本转 `archived`，已购订单仍保留旧版本快照。

### 4.11 `AgreementConsent` 签署凭证

| 字段 | 说明 |
|---|---|
| user_id / openid | 签署人 |
| user_snapshot | 姓名、手机号快照 |
| agreement_code / version / content_hash | 协议标识与内容指纹 |
| consent_token | 服务端签发的一次性凭证（5 分钟有效、一次性消费） |
| consented_at | 服务端时间 |
| client_ip / user_agent / device_model | 环境信息 |
| scene | `order_confirm` / `order_detail` / `esign` |
| order_no | 关联订单号（可为空，下单后回填） |
| signature_type | `clickwrap` / `esign` |
| esign_flow_id / evidence_url / certificate_no | 第三方电子签流程号、出证地址、存证编号（P1） |
| status | `valid` / `revoked` / `failed` |

索引：`consent_token` 唯一、`{user_id, agreement_code, consented_at}`、`{order_no}`。

## 五、商品类型与权益映射

| 商品类型 | 生成权益 | 预约方式 |
|---|---|---|
| 时间卡 | `UserPackage(package_type='time_card')` | 现有预约与周期限额 |
| 次卡 | `UserPackage(package_type='count_card', total_credits=N)` | 现有预约扣次 |
| 单次卡 | `UserPackage(package_type='count_card', total_credits=1)` | 现有预约扣次 |
| 私教课 | `UserPackage(package_type='count_card', total_credits=N, class_type_limit='private')` | 预约"私教"类型课程；普通套餐不可预约私教课 |
| 场地租用 | 不线上售卖 | 商城"场地租用咨询"入口 → 拨打门店电话 |

### 5.1 私教课设计

1. 管理端排课新增"课程类型"：大课（默认）/ 私教。
   - 私教课容量默认 1，可调整；教练必选；可设置舞种、时间、教室。
2. 私教商品 `benefit.class_type_limit='private'`；购买生成的 `UserPackage.class_type_limit='private'`。
3. 预约校验规则：
   - 私教课程（`Schedule.class_type='private'`）**仅允许** `class_type_limit='private'` 的套餐预约。
   - 大课（`group`）允许 `class_type_limit` 为 `null` 或 `group` 的套餐预约。
   - 存量套餐 `class_type_limit=null`，行为与现在一致（可约大课，不可约私教）。
4. 校验必须覆盖全部入口：会员预约、管理端代约、候补转正、现场签到、现场补签。
5. 会员端课程卡片：私教课显示"私教"标签；无资格时置灰并提示"需购买私教课包"。

## 六、微信支付接入设计

### 6.1 配置来源（按你的决策）

- 商户参数全部由管理员在管理端「购买设置 → 支付设置」录入，加密存库，不再写 `.env`。
- `.env` 仅新增一个服务器主密钥：
  ```
  PAY_CONFIG_SECRET=            # 32 字节随机串，用于加密支付参数
  ```
- 未配置主密钥时，服务启动告警，支付设置页禁止保存敏感项。

### 6.2 支付设置页字段与校验

| 字段 | 录入方式 | 校验 |
|---|---|---|
| 商户号 mchid | 文本 | 8-12 位数字 |
| AppID | 文本，默认带出会员端 AppID | 必须等于会员端 AppID，否则拒绝保存 |
| 证书序列号 | 文本 | 40 位十六进制 |
| APIv3 密钥 | 文本（密文） | 32 位 |
| 商户私钥 | 上传 `.pem` 或粘贴 | RSA 私钥可解析，且与公钥配对 |
| 微信支付公钥 | 上传 `.pem` 或粘贴 | RSA 公钥可解析 |
| 公钥 ID | 文本 | `PUB_KEY_ID_` 开头 |
| 回调地址 | 只读默认，可改 | HTTPS、无参数 |
| 启用真实支付 | 开关 | 配置自检通过后才允许开启 |

### 6.3 配置自检（"检测配置"按钮）

1. 私钥与公钥解析 → 签名一段随机串并用公钥验签 → 校验配对。
2. 用商户参数调用 `GET /v3/pay/transactions/out-trade-no/WQHEALTHCHECK000000?mchid=...`：
   - 返回 `ORDER_NOT_EXIST` = 签名、商户号、证书序列号全部正确。
   - 返回签名错误 = 明确提示哪一项有问题。
3. 结果以列表形式展示：商户号 ✓ / 证书序列号 ✓ / 私钥 ✗（原因）/ 公钥 ✓ / 回调地址 ✓。
4. 自检不创建订单、不产生费用。

### 6.4 支付时序

```
会员端                    后端                         微信支付
  │ POST /orders           │ 校验开关/上架/库存/限购/资格 │
  │───────────────────────►│ 建单 pending + 扣库存        │
  │ ◄──── 订单与金额 ──────│                              │
  │ POST /orders/:id/pay   │                              │
  │───────────────────────►│ POST /v3/pay/transactions/jsapi
  │                        │─────────────────────────────►│
  │                        │ ◄──────── prepay_id ─────────│
  │ ◄── 支付参数(签名) ────│                              │
  │ wx.requestPayment      │                              │
  │──────────────────────────────────────────────────────►│
  │                        │ ◄── 支付回调 ────────────────│
  │                        │ 验签/解密/金额校验/幂等      │
  │                        │ 建套餐 + 转正式会员 + 推送   │
  │ ◄── package_update ────│                              │
  │ POST /orders/:id/sync  │ 主动查单兜底                 │
  │───────────────────────►│─────────────────────────────►│
```

### 6.5 关键实现

- **下单**：`/v3/pay/transactions/jsapi`，`amount.total` 为分，`description` 为"商品名-门店名"，`time_expire` 15 分钟。
- **调起参数**：`appId/timeStamp/nonceStr/package=prepay_id=xxx/signType=RSA/paySign`，签名串 `appId\ntimeStamp\nnonceStr\npackage\n`。
- **请求签名**：`WECHATPAY2-SHA256-RSA2048`，签名串 `方法\nURL\n时间戳\n随机串\n请求体\n`。
- **回调**：保留 `rawBody`；用公钥验签；AES-256-GCM 解密；校验 `appid/mchid/out_trade_no/amount.total`；`notify_id` 唯一防重放；处理成功返回 200 `{"code":"SUCCESS","message":"成功"}`。
- **查单**：`GET /v3/pay/transactions/out-trade-no/{order_no}?mchid=`，仅 `SUCCESS` 且金额一致才发货。
- **关单**：`POST .../close`；关单前先查单，避免误杀已支付订单。
- **退款（P1）**：`/v3/refund/domestic/refunds`，本期只建表与状态，不开放入口。
- **发货信息**：支付成功后调用小程序 `upload_shipping_info`（`logistics_type=3` 虚拟/线下服务，以后台要求为准），失败只记录并重试，不影响权益。
- **Mock**：`PaymentConfig.enabled=false` 且 `NODE_ENV!=production` 时可用 Mock 支付（后台直接标记成功），生产环境禁止。

### 6.6 安全

- 金额、商品、门店、库存、限购、资格全部服务端计算。
- 支付配置只允许超管读写，敏感字段密文存储、接口永不回显明文。
- 回调免 JWT，但必须验签 + 防重放。
- 开票信息在管理端列表脱敏。

## 七、会员资格与自动转正

| 状态 | 商城浏览 | 下单 | 说明 |
|---|---|---|---|
| guest（未注册/被拒） | 可 | 否 | 提示"请先完善注册信息" |
| registered（审核中） | 可 | 可 | 支付成功后自动转正式会员 |
| official（正式） | 可 | 可 | 正常购买 |
| 账号被冻结/限制 | 可 | 否 | 展示限制原因 |

**转正流程（支付发货成功后执行一次，幂等）：**

1. `member_status: registered → official`。
2. 无 `member_code` 时调用 `generateMemberCode` 生成。
3. `user.store_id` 为空时绑定为商品归属门店（已有门店不覆盖）。
4. 写操作日志：`action='purchase_activate'`，详情含订单号、商品名、金额。
5. WebSocket 推送 `member_update`，会员端个人中心即时刷新为正式会员。
6. 订单详情与会员详情展示"购买转正"来源。

> 注意：`registered` 用户可能同时存在待审核的手机号/资料变更申请，转正不改变这些子状态，避免影响既有审核流程。

## 十二、一致性与并发（无事务）

1. **下单幂等**：同用户同商品存在未过期待支付订单时直接复用。
2. **库存**：`findOneAndUpdate({_id, stock:{$gt:0}}, {$inc:{stock:-1, sold_count:1}})`；关单/取消归还。
3. **限购**：统计已支付/已完成订单数，超限拒绝。
4. **发货幂等**：状态 CAS 抢占 `processing`；`transaction_id` 唯一；重复回调直接成功。
5. **补发**：发货失败每 10 分钟重试，最多 3 次，之后人工补发。
6. **关单防误杀**：先查单再关单。

## 十六、验收标准

### 16.1 功能

| 编号 | 场景 | 预期 |
|---|---|---|
| A1 | 管理端录入支付参数并检测 | 各分项结果准确；敏感项不回显明文 |
| A2 | 创建 4 类商品并上下架 | 字段校验正确；下架后会员端不可见不可买 |
| A3 | 库存与限购 | 不超卖；超限被拦截 |
| A4 | 购买时间卡 | 支付成功 → 待激活套餐 → 首次预约激活 → 扣课与限额正确 |
| A5 | 购买次卡/单次卡 | 次数正确，扣次正确 |
| A6 | 购买私教课 | 仅可预约私教课程；预约大课被拦截并提示 |
| A7 | 注册用户购买 | 支付成功后自动成为正式会员并生成会员编码 |
| A8 | 支付超时 | 15 分钟自动关单并释放库存 |
| A9 | 重复回调/重复点击 | 只生成一份权益，不重复扣款 |
| A10 | 发货失败 | 订单已支付，管理端可补发 |
| A11 | 关闭开关 | 入口消失、接口拦截；订单与发票仍可查 |
| A12 | 门店开关 | 仅该门店受影响 |
| A13 | 开票 | 登记 → 管理端开具/驳回 → 会员端可见 |
| A14 | 权限 | 店长本店；店员无权；会员仅看自己 |
| A15 | 协议确认 | 未勾选不可下单；版本/哈希/一次性凭证校验通过才建单；签署记录可查可导出 |
| A16 | 协议版本更新 | 新下单需同意新版本；旧订单仍展示下单时的历史版本快照 |
| A17 | 电子签（P1） | 未完成签署不可支付；签署回调后订单状态与存证信息一致 |

### 16.2 回归

- 管理员录入、激活、延长、作废、罚课、停卡、赠送全部正常。
- 套餐录入记录不出现自购记录。
- 预约、候补、签到、放假顺延、提醒、数据中心、WebSocket 无回归。
- 会员删除后订单/开票记录可查（快照完整）。

### 16.3 支付合规

- 验签失败拒绝并记录；金额/AppID/商户号/订单号不匹配不发货。
- 关单前查单，已支付不被误关。
- 密钥不出现在代码、日志、接口响应。

## 二十、电子协议签署合规方案（V3 新增）

### 20.1 结论先行

| 层级 | 适用 | 做法 | 证据力 |
|---|---|---|---|
| 基础层（本期 P0） | 全部订单 | 主动勾选 + 全文可查 + 版本号 + 内容哈希 + 一次性同意凭证 + 服务端时间 + IP/设备 + 订单绑定 + 不可篡改日志 | 中：能证明"展示过、同意过、内容未被改"，身份真实性依赖微信登录与手机号 |
| 增强层（P1） | 单笔 ≥ 3000 元、有效期 ≥ 12 个月、私教大课包等高风险订单 | 接入第三方可靠电子签：实名认证 + 人脸核身 + CA 数字证书 + 可信时间戳 + 区块链存证 + 出证报告 | 高：符合《电子签名法》"可靠电子签名"，可出证 |

**不建议自建 CA、时间戳与存证体系**：成本高、资质难、举证链条不完整，直接使用成熟第三方平台更稳。

### 20.2 法律依据

1. **《电子签名法》第十三条**：可靠电子签名需同时满足四项——签名制作数据专属于签名人、签署时仅由签名人控制、签署后对签名的改动可发现、签署后对数据电文内容和形式的改动可发现。
2. **《电子签名法》第十四条**：可靠的电子签名与手写签名或盖章具有同等法律效力。
3. **《民法典》第四百六十九条**：能够有形表现所载内容并可随时调取查用的数据电文，视为书面形式。
4. **《民法典》第四百九十六条**：格式条款提供方对免除或减轻其责任、与对方有重大利害关系的条款负有提示和说明义务，未履行则对方可主张该条款不成为合同内容。→ 退款限制、停卡规则、免责条款必须显著提示。
5. **《电子商务法》第三十一条**：商品和服务信息、交易信息应保存自交易完成之日起不少于三年。→ 本项目按 5 年保存。
6. **《人民法院在线诉讼规则》第十六条**：通过区块链存储且经技术核验一致的电子数据，可认定上链后未经篡改（有相反证据除外）。→ 第三方电子签的区块链存证具备司法实践基础。
7. **《个人信息保护法》**：实名信息、人脸识别属于敏感个人信息，需单独同意、告知处理目的与受托方。
8. **《单用途商业预付卡管理办法（试行）》**：记名卡不得设有效期、不记名卡有效期不得少于 3 年。→ 舞蹈套餐是否被认定为预付卡需属地商务部门确认，**这是本方案最重要的待法务确认事项**。

### 20.3 两种签署模式对比

| 维度 | 勾选同意（clickwrap） | 第三方可靠电子签 |
|---|---|---|
| 身份真实性 | 微信 openid + 注册手机号，较弱 | 身份证二/三要素 + 人脸核身，强 |
| 签名技术 | 无 CA 证书 | CA 数字证书 + 可信时间戳 |
| 防篡改 | 内容哈希 + 日志 | 哈希 + 区块链存证 + 司法链 |
| 举证材料 | 协议快照、同意记录、日志、订单与支付凭证 | 出证报告、存证证书、验签报告 |
| 成本 | 无额外费用 | 按份计费，需与服务商询价 |
| 体验 | 一步勾选，转化高 | 跳转 + 人脸，略有流失 |
| 适用 | 常规套餐 | 高客单、长周期、纠纷高风险 |

### 20.4 本期勾选签署的完整证据链（必须全部落地）

1. 协议全文入库，发布即固定 `version` 与 `content_hash`，之后不可原地修改。
2. 会员在确认订单页**主动勾选**（默认不勾选），可点击查看全文。
3. 点击支付前，服务端签发 `consent_token`（5 分钟有效、一次性、绑定 user + code + version + hash）。
4. 创建订单必须携带 `consent_token`；服务端校验版本为当前 `published`、哈希一致、凭证未消费。
5. 落库 `AgreementConsent`：user_id、openid、姓名与手机号快照、协议编码/版本/哈希、服务端时间、IP、User-Agent、设备型号、页面场景、订单号。
6. 订单保存 `agreement_version / agreement_hash / agreement_consent_id`。
7. 管理端订单详情可查看并导出签署凭证。
8. 会员端订单详情可查看下单时的协议历史版本。
9. 协议版本更新后，新订单需同意新版本，旧订单不受影响。
10. 存证：内容哈希每日汇总，可选写入可信时间戳或第三方存证（P1 随电子签一起接入）。

### 20.5 交互流程

**本期（勾选）**

```
商品详情 → 确认订单 → 点击协议名称查看全文（版本/生效日期）
        → 主动勾选 → 点击支付
        → POST /agreements/:code/consent 取一次性凭证
        → POST /orders 携带 consent_token
        → 服务端校验并落库 → 返回支付参数 → wx.requestPayment
```

**P1（第三方电子签）**

```
确认订单 → 需要电子签的商品 → 创建订单（pending_esign，30 分钟）
        → POST /orders/:id/esign 获取签署链接
        → 跳转电子签小程序/H5 → 实名 + 人脸 + 签署
        → 回调验签 → esign_status=signed → 订单转 pending_payment
        → 返回小程序继续支付
```

未完成签署不可支付；超时自动关闭订单并释放库存。

### 20.6 协议内容合规清单（需法务确认文本）

- [ ] 经营者主体名称、地址、联系方式、投诉渠道
- [ ] 服务内容、适用门店、舞种/时段/星期限制
- [ ] 有效期与激活规则（首次预约激活 / 手动激活 / 排队 / 2 个月兜底）
- [ ] 价格、支付方式、发票说明
- [ ] 退款规则（未使用全退 / 按剩余价值退 / 不支持退款），**加粗 + 单独确认**
- [ ] 停卡、转卡、延期规则
- [ ] 违约责任与免责条款，**显著提示**
- [ ] 未成年人购买与监护人同意条款
- [ ] 个人信息处理告知与第三方受托方（支付、电子签）
- [ ] 争议解决方式与管辖
- [ ] 协议版本号与生效日期
- [ ] 预付卡合规表述：避免"过期作废"等绝对表述，保留延期/退费通道

### 20.7 第三方电子签选型（P1）

| 服务商 | 优势 | 备注 |
|---|---|---|
| 腾讯电子签 | 微信生态集成最好，小程序内签署，人脸核身 + 至信链存证，司法判例较多 | 推荐首选，按份计费需询价 |
| 法大大 | 合同全生命周期能力成熟，API/SDK 完善 | 适合后续合同管理扩展 |
| e签宝 | 电子印章与企业签署能力强 | 适合企业侧与多主体场景 |

选型关注：小程序内闭环能力、实名/人脸合规资质、存证司法链、出证时效、单份价格、回调与幂等能力、数据存储地域与保密条款。

### 20.8 数据留存与举证

- 订单、协议快照、同意记录、支付记录保存不少于 **5 年**。
- 管理端支持导出"订单 + 协议快照 + 签署凭证"证据包。
- 发生争议时按"协议内容 → 同意行为 → 身份信息 → 支付记录 → 权益发放"形成完整证据链。
- 第三方电子签按服务商存证期限保存，并在本地保留流程号与出证地址。

### 20.9 待法务/属地确认的 5 个问题

1. 舞蹈套餐是否被认定为单用途商业预付卡；若是，记名卡有效期条款如何调整。
2. "未使用可全退、已使用按剩余价值退"是否构成不公平格式条款。
3. 未成年人购买是否必须监护人签署，如何识别与拦截。
4. 电子签启用阈值（默认单笔 ≥ 3000 元或有效期 ≥ 12 个月）是否合适。
5. 人脸核身的必要性与替代方案（如身份证二要素 + 短信验证）是否可接受。
